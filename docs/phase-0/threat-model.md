# Threat model — STRIDE and LINDDUN

Status: Proposed design; verification still pending. ASVS target: version 5.0.0 Level 2 including applicable Level 1 requirements. ISO security/privacy references are framework alignment, not certification. Boundaries are in [architecture](architecture.md).

Assets: identity sessions, account/preset/review ownership, exact search coordinates, consent evidence, provider credentials/content rights, licenses, moderation integrity, exports, encryption keys, backups, ranking fairness and CI signing authority. Actors: anonymous/registered users, malicious client, compromised provider response, malicious uploader/reporter, privileged insider, supply-chain attacker. Provider and browser data are untrusted.

## STRIDE

| ID | Threat and boundary | Controls | Required evidence / residual risk |
| --- | --- | --- | --- |
| S01 Spoofing | Stolen session, forged JWT, OAuth login CSRF, credential stuffing | OIDC code+PKCE, state+nonce, strict pinned alg/issuer/audience/time/JWKS allowlist; MFA/passkeys; session rotation, bot throttling, secure cookies | Forged/expired/alg-confusion/token substitution and OAuth state replay tests; IdP config review; recovery channels remain risk. |
| S02 Tampering | Mass assignment, SQLi, manipulated ranking/cursors, webhook replay | Strict allowlists/unknown-field rejection, parameterized queries, signed expiring query-bound cursors, canonical input, HMAC signatures/time/replay IDs | Fuzz/contract/injection tests and deterministic rank vectors; business data quality needs moderation. |
| S03 Repudiation | Claimed consent or moderator action cannot be proven | Append-only versioned consent, click-wrap record, transactional audit/outbox, authenticated actor and tamper-resistant sink | Alter/delete audit tests and access logs, no excessive identity leakage. |
| S04 Information disclosure | IDOR/BOLA, exports/cache cross-user leak, logs/location, exposed secrets | Default-deny ownership and scopes, RLS, private/no-store personal responses, redaction, field encryption/KMS, scoped short export URLs | Two-account negative authorization tests, log capture, cache isolation and KMS access reviews; UUIDs never substitute for authorization. |
| S05 Denial of service | Search/radius abuse, retry storms, image bombs, expensive filters | Caps/page limits, timeouts/bulkheads/quotas/cost circuit, 64 KiB JSON, upload bytes/pixel caps, WAF/CDN | k6 saturation/abort/429 tests and maximum-work assertions; outages degrade visibly. |
| S06 Elevation of privilege | Moderator/admin endpoint abuse, pool RLS contamination, compromised build | Separate scopes/roles, step-up auth, transaction-local context reset, no DB DDL for app, protected reviewed signed changes, isolated CI identity | Role/owner matrix tests, pooled-connection tests, branch settings screenshots/API evidence; organizational enforcement pending. |
| S07 XSS/SSRF | User review HTML, malicious embed/provider URL, server URL fetch | Text output encoding, no raw HTML review rendering, sanitized official embed template, egress host/IP allowlist, redirects off, metadata denial | Stored/reflected/DOM XSS and rebinding/redirect SSRF tests; official embed sandbox compatibility tests. |
| S08 CSRF/clickjacking | Cookie-auth side effect, framed consent/account deletion | __Host- session cookies, SameSite, Origin checks and CSRF token; CSP frame-ancestors none; destructive confirmation/step-up | Cross-origin/missing token tests, frame tests; UX confirmation cannot replace authorization. |
| S09 File/path attack | Polyglot upload, traversal, unsafe deserialization | Fixed random storage keys, type sniff/decode/scan/re-encode, data-only JSON schemas, no client filesystem paths | Malware/quarantine/EXIF/oversize/path vectors; no image release if scanning unavailable. |

## LINDDUN

| ID | Privacy threat | Design and proof needed |
| --- | --- | --- |
| P01 Linkability | Queries, source embeds and account can reveal date preferences | No saved precise location by default; no cross-site identifiers; avoid personal IDs in provider requests; consent-gated surfaces; network/log audit. |
| P02 Identifiability | Location, reviewer name and pseudonymous logs can identify people | PII schema, minimum provided source attribution, no query/coordinates in telemetry, field encryption, separated audit actor mapping; re-identification assessment. |
| P03 Non-repudiation privacy harm | Excessive proofs expose who visited or reviewed | Verified-account label only; minimal consent proof, no identity document by default, restricted audit, bounded retention; DPIA review. |
| P04 Detectability | Account enumeration/reset/export endpoints reveal presence | Non-enumerating IdP reset, uniform owner 404s, private DSR endpoints, quotas and response-shape checks; timing analysis. |
| P05 Disclosure | Backups, export URLs, expired cache or iframe transfers expose PII | KMS, TLS, limited lifetimes, immutable retention, export step-up, fail-closed cache expiry, no pre-consent requests; restore/DSR rehearsal. |
| P06 Unawareness | Bundled consent, hidden profiling/FX/ranking/content sampling | Plain bilingual notices, equal accept/reject, distinct marketing/terms/location/embeds, visible priority/explanations and source coverage; usability tests including disabled users. |
| P07 Non-compliance | Invalid vendor grant, unlawful retention, jurisdiction assumptions | Versioned policies/consent, legal modules, DPA/transfer inventory, deadline tracking, license inventory, counsel launch gates; legal review record. |

## Security baseline specification

TLS 1.3 preferred, minimum 1.2 at edge and internal service connections. HSTS `max-age=31536000; includeSubDomains` only after all domains support TLS; preload requires separate domain readiness review. Nonce-based CSP: default-src self, script-src self + per-response random nonce + approved provider hosts on opt-in routes; object-src none; base-uri none; frame-ancestors none; restrictive connect/frame/img/style policies validated for actual SDK behavior. No unsafe-inline/unsafe-eval blanket exception. Escape user data before any JSON/HTML interpolation. Nonce must not be reused through shared HTML caching.

Headers: nosniff; Referrer-Policy no-referrer (privacy-sensitive pages); Permissions-Policy geolocation=(self), camera=(), microphone=(), payment=(); COOP same-origin except reviewed popup/login compatibility route if required; COEP require-corp and CORP same-origin on isolated core routes. **Explicit proposal requiring approval:** official map/social routes may require COEP unsafe-none and cross-origin resource exceptions when providers do not supply compatible CORS/CORP. Keep frame-ancestors and restrictive CSP; no claim of universal isolation. Record route/header test evidence. SRI on immutable third-party scripts with CORS support; use bundled/self-hosted assets where licensed. Dynamic official Google/social loaders may not expose a stable SRI hash: document an approved exception using strict host list, nonce, consent and supply-chain monitoring. Test OIDC popup behavior against COOP; prefer redirect flows.

Browser cookies: opaque `__Host-aroundate_session`, Secure HttpOnly SameSite=Lax Path=/, no Domain; CSRF token cookie if double-submit is used must be signed/session-bound (and readable intentionally), not the session token. Login creates new session ID; privilege changes/recovery revoke/rotate; idle 30m/absolute 12h proposed. No secrets in JS localStorage. Rate limits are distributed and owner/IP-hash scoped with short-lived rotating keys; logs do not retain raw IP.

Identity configuration: Argon2id measured memory/time cost, breached/common-password blocklist, at least 15 characters for single factor, support >=64-character passwords and Unicode with specified normalization; no composition rules or forced periodic changes absent compromise. Allow paste/password managers. Non-enumerating reset, single-use expiring tokens, revocation after reset, passkey/TOTP enrollment with recovery protection. Verify these requirements in the chosen IdP, including extensions; do not assume defaults. Privileged roles require MFA, scoped service identities, separate environments and least privilege.

Secrets use managed vault references, regular and incident-driven rotation, short-lived deployment credentials, restricted public Maps key. Webhooks only for supported approved events: signature on exact raw bytes, constant-time verify, narrow timestamp tolerance (initial 5m), unique event replay store and idempotent handler. Unknown/inactive callbacks reject. No generic arbitrary provider URL fetch or open redirect; redirects only internal allowlisted destinations.

OWASP coverage: injection/output encoding, broken auth/access control, misconfiguration, cryptography, logging/monitoring, vulnerable dependencies, integrity/supply chain and SSRF all map to rows above and quality gates. OWASP API Security Top 10 mapping includes BOLA/BFLA, broken auth, property authorization, resource consumption, sensitive business flows, SSRF, config, inventory and unsafe API consumption. Freeze applicable published Top 10 editions at Phase 1; map actual versioned ASVS controls individually, not claim an unverified full control audit.
